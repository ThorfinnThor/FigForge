# FigForge – Übergabe (Stand 2026-10-22)

Diese Datei hält fest, wo das Projekt steht, was zuletzt geändert wurde, wie die Automatisierung funktioniert und was offen ist. Sie folgt der Pflichtübergabe aus `AGENTS.md` (geänderte Dateien, ausgeführte Befehle und Tests, Ergebnisse, bekannte Einschränkungen, offene Risiken). Zahlen sind mit Datum versehen; was nicht geprüft wurde, ist ausdrücklich so gekennzeichnet.

## 1. Überblick

- **Produkt (Name seit 2026-10-22: „Create Your Minifig“, intern weiter „FigForge“):** backendloser Minifiguren-Konfigurator mit 3D-Vorschau (LDraw/Three.js) und Teilelisten-Export (BrickLink-XML, Rebrickable-CSV, Pick-a-Brick-CSV). Live unter https://createyourminifig.com.
- **Technik:** React + Vite, Daten statisch im Repo, Entwürfe lokal im Browser (IndexedDB). Kein Backend, keine Konten.
- **Deployment:** ausschließlich Cloudflare Workers Builds nach einem Merge auf `main`. GitHub Actions deployt nicht.
- **Regeln:** `AGENTS.md` ist verbindlich (ADR bei Architekturänderungen, generierte Daten nicht von Hand ändern, Tests nicht passend zur Implementierung umdefinieren). `main` ist geschützt: Änderungen nur per PR, Branch muss aktuell sein, `verify` muss grün sein.
- **Quellenregel (angepasst 2026-10-19, vom Eigentümer freigegeben):** Rebrickable Catalog Downloads/CSV. Einzige Erweiterung für BrickLink-Artikelnummern: der offizielle BrickLink Catalog Download als hashgebundener Snapshot (Rohdateien werden nicht veröffentlicht) und offizielle LDraw-Header. Keine MOC-Dateien, weder Rebrickable- noch BrickLink-API.

## 4. Automatisierung (`.github/workflows/refresh-catalog.yml`)

**Zeitplan:** Montags 04:17 UTC (GitHub startet verzögert; am 2026-10-19 um 09:59 UTC, erfolgreich). Manuell startbar über `workflow_dispatch`. Nächster planmäßiger Lauf: 2026-10-26 (erster Lauf mit Auto-Merge).

**Ablauf:** Rebrickable-CSV laden → offizielle LDraw-Bibliothek prüfen/übernehmen → Builder-Katalog, Abdeckung, Platzierungskandidaten neu bauen (dabei: Crosswalk abgleichen, Exportpakete bauen) → Accessory-Review neu bauen → Suchindex bauen → `verify` → Automations-Branch `automation/rebrickable-catalog-refresh` pushen → Review-PR anlegen/aktualisieren → bei grünem `verify` Auto-Merge einschalten (ADR-042) → CI per Dispatch anstoßen (nur ohne Token) → BrickLink-Snapshot-Alter prüfen.

**Verhalten bei Problemen:**
- `verify` schlägt fehl → PR wird trotzdem als **Entwurf** angelegt, Lauf endet rot, Issue `Katalog-Refresh fehlgeschlagen` (Label `catalog-refresh-failed`). Nächster grüner Lauf schließt das Issue.
- Geprüfte Teilenamen weichen ab → `npm run data:check:name-drift` listet alle; gepinnte Namen in `data/curated/*` nach Prüfung anpassen (nur Umbenennung, nicht anderes Teil). Kommas, Groß-/Kleinschreibung und Leerraum werden ignoriert.
- `inventory_minifigs.csv.gz` mit verwaister Inventar-ID → die Zeile wird übersprungen und im Bericht (`skippedInventoryMinifigRows`) gezählt; erst über 0,5 % der Zeilen bricht der Lauf ab (ADR-039).
- Neue Teile ohne BrickLink-Zuordnung → Status `not-in-snapshot`, für BrickLink gesperrt; ID nur bei eindeutigem offiziellen LDraw-Header.
- BrickLink-Snapshot älter als 90 Tage → Issue (Label `bricklink-snapshot-stale`) mit Anleitung; wird nach dem Import geschlossen.

**Manuelle Schritte, die bleiben:**
1. **Refresh-Token:** läuft ab (spätestens ein Jahr nach Anlage); Ablaufdatum im Kalender führen. Siehe Abschnitt 4.
2. **Branch aktualisieren**, wenn `main` weitergezogen ist und der Auto-Merge deshalb nicht greift (`gh pr update-branch <nr>`); ein grüner Refresh-PR mergt sich sonst selbst. Entwürfe (Validierung fehlgeschlagen) werden nie automatisch gemergt.
3. **BrickLink-Snapshot erneuern** (spätestens alle ~90 Tage): auf bricklink.com anmelden, im Catalog Download die Tabellen *Parts* und *Part and Color Codes* (txt) laden, dann `npm run data:import:bricklink -- <Parts.txt> <Part-and-Color-Codes.txt> YYYY-MM-DD` und das Ergebnis per PR einreichen. Rohdateien nicht committen.

Neue öffentliche Seiten müssen in `src/seo/routes.ts` stehen, sonst liefert Cloudflare 404. Adressen haben keinen Schrägstrich am Ende.

Neuer Ratgeber: Eintrag in `GUIDE_SLUGS` und `GUIDE_DATES`, Texte `guide.<id>.metaTitle|metaDescription|title|lede` und Abschnitte in beiden Sprachen; ein Test prüft die Vollständigkeit.
- **Routen und SEO:** Neue öffentliche Seiten in `src/seo/routes.ts` eintragen (Titel/Beschreibung/`h1`-Schlüssel in `src/i18n.tsx`, deutsch und englisch). Ein Test prüft, dass die Texte existieren. Inhaltsseiten bekommen ihren Text über eine `page`-Art in `src/seo/routes.ts` und einen Baustein in `src/seo/page-bodies.ts`.

## 7. Offene Punkte und Risiken

1. **Token für Refresh-PRs (Entscheidung Eigentümer; Empfehlung: Fine-grained PAT, nur dieses Repo, ein Jahr Laufzeit, als Secret `REFRESH_PR_TOKEN`).** Workflow ist vorbereitet (#146). Anlegen: https://github.com/settings/personal-access-tokens/new (Repository access: nur `FigForge`; Repository permissions: Contents und Pull requests je „Read and write“), dann das Secret unter https://github.com/ThorfinnThor/FigForge/settings/secrets/actions/new speichern. Branch-Schutz auf `main` (geprüft per API): `verify` Pflicht, Branch muss aktuell sein, gilt auch für Administratoren, keine Force-Pushes, keine Pflicht-Reviews.
2. **Rechtlich ungeprüft:** Nutzungsbedingungen des BrickLink Catalog Downloads für die Veröffentlichung der abgeleiteten Zuordnungstabelle in einem öffentlichen Repository. Vor einem breiten Start klären.
3. **Rechtstexte:** Impressum (#142), Datenschutzerklärung (#153) und Marken-Hinweis (#145) sind live, aber **nicht rechtlich geprüft**. Offen aus `docs/legal/datenschutzerklaerung-entwurf.md`: (a) Das Cloudflare-DPA wurde im Konto nicht gesondert akzeptiert; Cloudflare schreibt, es gelte für Self-Serve-Kunden und sei Teil des Vertrags, ob das ohne Zustimmung wirkt ist ungeklärt (Support fragen oder Prüfung). (c) Amazon-Teilnahmevereinbarung nicht abrufbar. (d) § 25 TDDDG-Einschätzung zur lokalen Speicherung. (e) Banner, Google-Analytics-Abschnitt und der Satz zu Googles Datenverarbeitungsbedingungen (siehe Punkt 11).
4. **Noch nicht belegt:**
